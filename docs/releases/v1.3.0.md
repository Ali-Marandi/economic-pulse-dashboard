# Economic Pulse v1.3.0 — Windows Desktop Workspace

## Release summary

Economic Pulse v1.3.0 turns the existing dashboard into a more complete Windows desktop workspace for monitored macroeconomic analysis. The release connects the enterprise scenario workspace to the main dashboard, replaces placeholder reporting controls with local exports, hardens the Electron shell, and ships branded Windows installation assets.

> Generated reports and scenario outputs are local analytical aids. They are not forecasts, investment advice, or substitutes for documented analyst review.

## Highlights

| Area | Included in v1.3.0 |
|---|---|
| Decision workspace | The explainable scenario-analysis and local scenario-library panel is available from the overview dashboard. |
| Reports | Daily and weekly local reports can be generated and saved from the Reports page. |
| Exports | Current dashboard data can be exported as PDF, CSV, and an Excel-compatible workbook. Desktop users receive a native Save dialog. |
| Windows shell | The application uses a single-instance window, process sandboxing, isolated renderer context, navigation restrictions, denied permission requests, limited IPC, and an embedded local service. |
| Installer | Branded x64 NSIS installer with Start Menu and desktop shortcuts, plus a portable executable. |
| Delivery automation | The Windows release workflow now uses lockfile-based dependency installation before testing and packaging. |

## Installation

Download the installer and run `Economic-Pulse-1.3.0-win-x64.exe`. The assisted installer supports a user-selected installation directory and creates the configured shortcuts. For a portable workflow, download `Economic-Pulse-1.3.0-portable.exe` and run it from a directory where the user has write access.

## Verification performed

The release pipeline was exercised from a clean lockfile installation: dependency installation, static type checking, automated tests, production build, and creation of both Windows executables completed successfully. The release workflow should run the same quality gates before publishing a tagged GitHub release.

## Operational notes

A code-signing certificate and release-update channel are not configured in the repository. Before distributing beyond trusted testers, configure Authenticode signing and define the managed update policy. The local production preview also requires the deployment OAuth configuration before authenticated dashboard pages can be manually explored.
