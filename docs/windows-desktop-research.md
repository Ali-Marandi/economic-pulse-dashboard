# یادداشت‌های پژوهش: نسخهٔ دسکتاپ ویندوز

## مبنای تصمیم‌ها

نسخهٔ موجود از Electron با `contextIsolation`، `sandbox` و `nodeIntegration: false` استفاده می‌کند؛ این‌ها با راهنمای رسمی امنیت Electron هم‌راستا هستند. برای نسخهٔ تجاری، مسیرهای ناوبری و پنجره‌های جدید باید صریحاً محدود شوند، رابط IPC صرفاً با پیام‌های اعتبارسنجی‌شده گسترش یابد، و محتوای بیرونی هرگز با دسترسی Node بارگذاری نشود.[1]

بسته‌بندی موجود از هدف‌های NSIS و Portable برای ویندوز استفاده می‌کند. حفظ `appId` فعلی برای سازگاری ارتقا و حذف نصب مهم است؛ پیکربندی NSIS می‌تواند نصب تعاملی، مسیر نصب قابل‌انتخاب و میانبرها را فراهم کند.[2]

به‌روزرسانی خودکار عمومی را فقط زمانی می‌توان فعال کرد که کانال انتشار و امضای کد مشخص باشد. راهنمای Electron برای مخازن عمومی، انتشارهای GitHub و استفاده از سرویس به‌روزرسانی را توضیح می‌دهد؛ اما افزودن آن بدون تصمیم محصول دربارهٔ کانال پایدار/آزمایشی و گواهی امضا مناسب نیست.[3]

## دامنهٔ پیشنهادی این انتشار

این نسخه روی کیفیت محصولیِ قابل‌آزمون تمرکز خواهد داشت: اتصال واقعی پنل تحلیل سازمانی به داشبورد، توانمندی‌های محلی دسکتاپ برای ذخیره‌سازی و صدور گزارش، پوستهٔ Electron مقاوم‌تر، نسخه‌بندی و بسته‌بندی رسمی، و مستندات انتشار. راه‌اندازی به‌روزرسانی خودکار و امضای کد به پیکربندی انتشار و گواهی مالک مخزن وابسته است و جداگانه آماده می‌شود.
